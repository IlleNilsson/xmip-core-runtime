# xmip-core-runtime

The Xmip runtime: a node started from its configuration and the technologies its program links, the message path it runs, and the native library the operator surfaces load.

**A node running.** `running::Running::start(path, linked)` runs ADR-0018's nine startup phases (`src/running.rs`, the phases' work in `src/startup.rs`, their names in `src/service.rs`): it reads the node's configuration and every Xmip Application it binds, each the configuration's `[[xmip_applications]]` section of its name (`start::read`), builds and validates the execution tree — the bound Receive Ports with each Receive Location's interaction and depth, and the Send Ports it takes with their policy, among it — with every Location held to its technology's settings declaration, and refuses — before anything serves — a transport, an accepted mechanism or a filter name the program was not built with, an accepted Party `[[parties]]` does not declare, a `[provision.receive]` that does not read (`src/receive_certificate.rs`), a contract at a Location (arrival holds no Stream to one yet), and a Module needing a Host Service in a process of its own. It plans the Host Services the started Modules need (`src/host.rs`, one host-type rule: what a Module is written in), loads each technology the configuration uses once — carrying its declaration into the catalogue — and opens each `[[modules]]` library once through the C ABI (`src/library.rs`, behind `dynamic-loading`), registers every capability once (`src/capability_registry.rs`), builds each Location's transport once from its address and settings and gives it the node's location as it does (`transport::Configured::open`, then `Configured::on_node` with `running::publication::location`, the owner's *Option A*, 2026-10-03 — the file transport claims in that name and returns what it still held there; so a Receive Location keeps its listener or session between receives) and the guard its receives terminate TLS with, the node's `[provision.receive]` certificate and anchors (`Configured::guarded_by`; a Location asking for TLS on a node with none is refused), reaches Xmip Storage (`src/storage.rs`, below), builds the `Runtime` once — the route gathering compiled then (ADR-0066) — and serves every Receive Location on a thread of its own: `Receiving::serve` (`src/receiving.rs`) takes what arrives — at most as many arrivals as the Location's pool has threads free and the node's carry budget has places (`Transport::receive_up_to`), waiting for a place where the node has none, the rest left at the far end (`src/budget.rs`: `budget::NodeBudget`, the node's `Budget`s beside each pool — the arrivals carried at once across every Location and the bytes they hold, and the bytes the sends hold; `tests/ledger/roomed.rs`; open problem 38, 2026-10-19) — and carries each arrival on the Location's pool (`src/pool.rs`: a dynamic, bounded pool of scoped threads, never below one, growing while work waits up to `pool::Limits::per_hardware_thread` — for a Receive Location twice the machine's hardware threads (`pool::hardware_threads`), calculated as the node starts — and shrinking after a minute idle; a piece of work that panics ends that piece, not its thread, and a thread is counted out however it ends), one thread carrying one arrival through the whole cycle and telling its far end the verdict — a carry that panics tells it `Failed` on the way out, so the far end keeps the Stream to send again and the Location settles the arrival as failed rather than waiting for it, and its stop with it — the arrivals of one receive told in the order they came and all of them before the transport is asked again; a transport whose receive waits for what arrives (`transport::Waiting::Waits`) is asked again at once, and one whose receive looks and returns at once (`Polled`) rests `[tuning] receive_poll` after a receive that found nothing — `receive_sweep` where its far end tells of a change (`transport::Notice`), a drop directory the runtime watches (`directory_watch`), and the word ends the rest at once (`receiving/watched.rs`, `stopping::Nudge`; ADR-0024, amendment 2026-10-20) — and `receive_backoff` after one that failed in a way asking again may mend, each from when that receive began (`receiving::Pace`, `src/receiving/pace.rs`), on the node's stop (`src/stopping.rs`: `stopping::Stopping`, whose raise wakes every rest at once; `tests/ledger/paced.rs`); `message_path::carry` runs each Stream through arrival, routing and Publication into the Ledger — the receive cycle sends nothing — and `Carried::cycle` says whether the receive cycle completed — accepted and durable, to be acknowledged — or was refused or failed (`ReceiveCycle`). `stop` drains: each Receive Location takes nothing more once its current receive returns (the technology's own wait bounds it) — except that one whose receive waits and whose far end already let go of what it handed over (`transport::Acknowledgement::at_most_once`: raw TCP, a datagram) first goes on receiving until a receive finds nothing, never past `[tuning] receive_drain` from the stop, so a connection queued in its listener's backlog before the stop is taken rather than closed away (`src/receiving/drain.rs`; `tests/ledger/drained.rs` fills the backlog before the stop on every machine; ADR-0018, amendment 2026-10-15) — what it took is carried whole, then the transports and loaded Modules are let go. `outcomes` and `snapshot` say what became of every Stream and what the node is doing; `publication` (`src/running/publication.rs`) is that snapshot at the node's `location`, `xmip:///<cluster>/node/<name>` — itself, its System Process, what it declares, each module, Location and Subscription, the figures at the stage that counts each kind, its Subscriptions' standing, and each Receive Location, Send Port and Send Location whose `start` does not say `true` — known, opened by nothing, Done and saying `configure::NOT_STARTED`, "not started: the configuration does not say true" (`ExecutionTree::not_started`; the owner, 2026-10-13) — with the node drawn by `observe::topology::draw` and `party`, the Party on each side `any-party` while the publication does not say which Parties a Location's `accept.party` takes; `running::publication::stopped` (`src/running/publication/stopped.rs`) is what it leaves once drained, the node Done and its pauses and what it never started standing. `xmip-service` writes it to `<data>/snapshot.toml` (ADR-0018, amendment 2026-09-30).

**What the program links.** The runtime names no technology (`architecture.toml`: a platform service depends on no technology repository). The program that starts a node hands over what it was built with as `linked::Linked` — its transports (`LinkedTransport::of::<T>()` over `transport::Configured`), route technologies, authenticators, policies and identifiers, and the policies set up from the Locations a node starts (`Linked::location_policies`, each handed, as the node starts, the gates of its Receive Locations and its Send Locations, `linked::Started`; ADR-0068, amendments 2026-10-19 and 2026-10-20) — and the node takes what its configuration names (ADR-0025). ADR-0018's amendment of 2026-09-26 makes that program `xmip-service`, an executable of the estate's root crate that links technologies by build feature. It was built on 2026-09-28. It runs a node until the operating system's service manager or the console stops it, then calls `Running::stop`. The runtime's own tests are a program too: they link `xmip-core-transport-tcp` and start a node that receives and sends over loopback. The stand-ins they run a node's gates with — an authenticator verifying with the verdict it was given, a policy allowing what the gates authenticated — are `fixture`, placed once behind the `test-support` feature, which only the crate's dev-dependency on itself enables, so its unit tests and `tests/ledger` share them. `Running::cluster` and `Running::node` give the node's place, and `Running::location` the location `xmip-service` declares, `xmip:///<cluster>/node/<node>` (ADR-0053).

**As a service.** `src/registration.rs` is the one place that writes what a service manager is told about a node's Xmip Service: a systemd unit (`Type=notify`, `Restart=on-failure`, `RestartPreventExitStatus=` the refused exit code `REFUSED`), a launchd property list, or the `sc.exe create` arguments and the settings that finish them (`windows_service_settings`: the description, and the environment the service is handed, such as `XMIP_AUDIT_DIRECTORY`). It runs `xmip-service --configuration <path>` under the name `node_service_name(node)`, `xmip-<node>`, and quotes a path that has a space. `xmip-service --definition` prints it, and `xmip-service --install`, which every package runs, applies it (ADR-0015, amendment 2026-10-13). `src/service_control.rs` asks this platform's service manager to start or stop a node's installed service by that name: `sc.exe`, `systemctl --no-block` or `launchctl`, chosen at compile time. It returns when the manager has accepted the request, and a manager's refusal comes back in the manager's own words. Nothing in the runtime applies a registration or restarts a service.

**The message path.** Arrival (`src/arrival.rs`) runs the transport gates against the Receive Location's `ReceiveGate` — the closed set of mechanisms its configuration's `accept` names (ADR-0019 clause 1), each verified by a linked authenticator, and the Parties it names, a verified identity resolved to the `[[parties]]` Party holding its value under the mechanism that verified it, for receive, by the id written with the Party (`src/recognized.rs`; the owner, 2026-10-19) and refused where it resolves to another or to none (ADR-0019, amendment 2026-10-19) — then creates the Message, runs the message gates, promotes every name the Subscriptions' filters use through the `route::Gathering` the Runtime was built with (a bare name is context, a prefixed one is read by its technology, a Null is absent, bytes refuse the Message; ADR-0046), opens the Journey and publishes. **The Ledger** (`src/ledger.rs`, `runtime-model.md` sections 3 and 5): once the transport gates pass — a refusal keeps nothing — arrival reads the arrival's body — `receive::ReceivedStream::body`, the transport's reader — into Xmip Storage in chunks, unsynced, by `ledger::write_stream(storage, stream, &mut reader, chunk)`, and from there holds the Stream as kept (`ledger::Kept::stream`: `stream::Stream::kept` over `ledger::Chunks`, read back a chunk at a time up to the first it does not hold, where the Stream ends, and held to the length the Stream's own record keeps — written once, with its last chunk, the one home of its length and of the SHA-256 digest `write_stream` takes of its bytes as they pass once (ADR-0070), which every Message referring to the Stream refers to; the reading is Xmip Storage's one chunk reader, `persist::storage::ChunkReader`; a chunk lost after Publication is refused in words), so nothing holds the whole Stream where the far end streams it: a gate that reads the content whole loads it once (`Stream::load`), a Stream that could not be read back fails the cycle rather than route on nothing (`Stream::unread`), and departure never reads it whole: its transport is handed it a chunk at a time (`transport::Outgoing`), each chunk read once from Xmip Storage for every departure of the same Stream on the node keeping up (`src/stream_share.rs`, over `persist::storage::ChunkReader::shared` and `next_chunk`), a read keeping one chunk for a departure alone and `KEPT_PER_READER` for each other, a departure about to let go of the chunk another of its read takes next waiting for it at most what the kept chunks take the read to pass, over the whole Stream for each departure waited for (`src/stream_share/one_read.rs`), one further behind reading the chunks it missed from the chunk it reached (`ChunkReader::shared_from`) from a read of its Stream that reaches its place, or one of its own the next behind shares, and moving before each chunk to a read that reaches it and more departures read, so the reads come together as their places meet (ADR-0018, amendments 2026-10-20); `tests/ledger/bounded.rs` carries 64 MiB in chunks holding a few chunks at most; `carry` then writes the Publication — the Message record (`message::Message::record`), a Journey per matched Subscription and per Send Port it reaches — one per Port of a Send Port Group, each naming its `send_port` (`ledger::opened`, over `Pickup::reaches` and `ConfiguredSubscription::ports`; `journey::Journey::matched`, its `record`) and the Publication's audit record in the audit capability's form, carrying the Message in full and every Stream its Sections are over, whose bytes the audit keeper keeps beside it (ADR-0070; `ledger::audited`, `tests/ledger/audited.rs`) — as one write whose one sync makes the chunks durable with it, before the cycle is reported completed; a writer's audit chain as Xmip Storage keeps it is walked by `ledger::verify_audit_chain` — each kept record in its number's order, its Streams' records and its body read a chunk at a time and held to its digest, digested by persist's `chain_digest` and walked by `xmip-core-audit`'s `audit_chain::walk`, which says where it breaks (ADR-0070 clause 5; `src/ledger/audit_chain.rs`); every record of a Journey, a Message and an audit record the runtime writes is made in one place, `ledger::journey_record`, `ledger::message_record` and `ledger::audit_entry` (`src/ledger/record.rs`), carrying beside its body the facts Xmip Storage keeps in searchable columns, found through `XmipStorage::query` (proposed 2026-10-09; `tests/ledger/searched.rs`); a Message nothing matched is kept with its entry in the node's Dead Message Queue in that same write (`src/dead_message.rs`: the receive context, what the gates concluded, the promoted properties `Arrived::Unroutable` carries, and every Subscription's decline; `tests/ledger/dead_message_queue.rs`). **The Dead Message Queue** is read and replayed through the pickup (`src/pickup/replay.rs`): `Pickup::dead_messages` reads the oldest of it for the node's snapshot (`pickup::PUBLISHED`, a hundred), and `Pickup::replay`, the Operator's act, routes an entry's promoted properties against the node's Subscriptions of now and writes the Journeys it opens (`ledger::opened`, the one place a Publication's Journeys are opened), each held in its Subscription's queue and picked up as a resume picks up, with the entry taken out and its audit record, carrying the Message as the Ledger keeps it, as one write, once; a Message that still matches nothing stays, refused with every decline. An order on the noun `dead-message` reaches it as Pause does (`xmip-service`'s `orders.rs`, the Playground's `operator_orders.rs`). Xmip Storage failing either is `Arrived::Failed`, counted as `Outcomes::failed`, and not acknowledged. The chunk is `[tuning] segments` TCP segments of `[tuning] tcp_segment` bytes, by default `ledger::CHUNK`: 44 (`ledger::SEGMENTS`) of 1460 (`transport::TCP_SEGMENT`), 64,240 bytes. **`[tuning]`** (`src/tuning.rs`; ADR-0031, amendment 2026-10-03) is every outward and hardware assumption the node runs by — the chunk, a Receive Location's pool (`receive_threads_per_hardware_thread`, default `pool::RECEIVE_THREADS_PER_HARDWARE_THREAD`, and `receive_idle`, default `pool::RECEIVE_IDLE`), how long a polled Receive Location rests (`receive_poll`, `receive_sweep` and `receive_backoff`, defaults `receiving::RECEIVE_POLL`, `receiving::RECEIVE_SWEEP` and `receiving::RECEIVE_BACKOFF`) and how long a stopping one drains (`receive_drain`, default `receiving::RECEIVE_DRAIN`), each read of a TLS handshake a Receive Location terminates, apart from its own wait (`receive_handshake`, default `transport::guard::HANDSHAKE`, five seconds; 2026-10-20), the Send pool and its claims (`send_threads_per_hardware_thread`, `send_idle`, `send_lease`, `send_scan`, defaults `send_step::SEND_*`), the oldest failed Journeys of each Send Port the node keeps (`failed_window`, default `send_step::FAILED_WINDOW`), the node's budget beside its pools (`node_receive_threads_per_hardware_thread`, `receive_chunks_per_thread` and `send_chunks_per_thread`, defaults `budget::NODE_RECEIVE_THREADS_PER_HARDWARE_THREAD`, `budget::RECEIVE_CHUNKS_PER_THREAD` and `budget::SEND_CHUNKS_PER_THREAD`) and the Storage client's `storage_timeout` and `storage_pass_over` (persist's `client::TIMEOUT` and `client::PASS_OVER`), and how long a surface's call to the node's local endpoint waits (`local_timeout`, default `plane::remote::LOCAL_TIMEOUT`, two seconds; the owner, 2026-10-13) — declared once as `tuning::TUNING` in `xmip-core`'s settings shape, read through it into the execution tree (`ExecutionTree::tuning`) and refused at phase 3 where a key is unknown, of the wrong kind or out of bounds; the constants are its defaults only. `start::validate` validates a cluster's `xmip.toml` node by node, each slice as `configure::slice` writes it, every problem opening with the node's location. **The send step** (`src/send_step.rs`, `runtime-model.md` section 10, built 2026-10-03) sends every Journey from the Ledger: the Publication keeps each Journey that is not held in the queue of where it leads (`sending::queue`, the name-based identifier of `<cluster>/<kind>/<name>`, the same on every node) and, where this node sends that Send Port and it is not Sequential, claims it in the same write and hands it to the node's Send pool in memory (`SendStep::line_up`, `SendStep::handed`), so the send starts without a sync of its own — as many as the pool admits; `send_step::dispatch` runs the pool (`[tuning] send_threads_per_hardware_thread`, `send_idle`), and each pass (`send_step::send`) tries the Send Port's Locations in order, retrying and failing over as its policy says (`sending::Port`), and hands on in one write — Completed and out of its queue, Failed with why and kept in its queue for an operator (blocking its sequence where a Sequential Port's `on_failure` says `block`), or Recovering with its due time kept at its place in its queue and its claim released (`HandOn::waits`), a retry's backoff holding no thread, no claim and no place in the Send pool, a scan passing over it unclaimed until it is due and taking it up then, on any node — the node keeping per queue only the earliest due time and how many wait (`send_step::due`), as Xmip Storage counts and tells them (`persist::storage::DueQueue`) and noted by each hand-on Xmip Storage took since its queue's read began, so a read that passed a Journey's place before its hand-on landed does not lose its due time, and waking for it at that time, not at the next `send_scan` (`send_step::due`'s tests) (open problem 43, corrected 2026-10-16; `tests/ledger/send_waiting.rs`: a far end that fails every send leaves a healthy Port's sends untouched, and a restart keeps every due time) — its tries the Journey's `attempts`, so a retry's count survives a restart (built 2026-10-04); a pass whose claim was not surely this node's when it began tries nothing and writes nothing, its claim given back and its queue read again (`Ended::Untried`). An Operator's **Retry** and **Dismiss** of a failed Journey (`SendStep::act`, `src/send_step/journey_act.rs`; `xmip_operate.h` section 16, `src/ffi/journey.rs`; an order on the noun `journey` through `xmip-service`'s `orders.rs`) are each one hand-on under a claim, audited: Retry writes it Active and moves it to the end of its Port's queue (`HandOn::requeued`), keeping its place where it blocks a Sequential Port; Dismiss writes it Dismissed and takes it out, so its sequence goes on (`tests/ledger/journey_act.rs`). A Send Port Group's Journeys are one per Port, each sent alone (`tests/ledger/send_group.rs`). As the node starts and every `send_scan` after, what is due in each queue this node sends is read — only what is due, through Xmip Storage's index of when each Journey is due (`XmipStorage::read_due`, `src/send_step/reading.rs`; ADR-0013, amendment 2026-10-21), so a scan's cost follows what is due, not what is held; a Sequential Send Port's reads beside it what holds a sequence behind it, a retry not yet due and, where a failure blocks, what failed, and goes through it in the queue's order — and every Journey no live claim holds is claimed and sent (recovery, and failover by a lapsed claim); a Sequential Send Port sends one Journey of each sequence (its `order_key`'s value) at a time, oldest first; in-flight claims are renewed on a thread of their own every third of a lease; what waits for a retry holds no claim, so a stop has none to give back. **A renewal's answer is acted on** (`src/send_step/renewal.rs`, corrected 2026-10-06): one that finds the claim another's stops every further Location of the pass and writes nothing, the loss counted at the Port and audited; one Xmip Storage does not answer leaves the claim unconfirmed — the Port Done from the first, a flat-out error — and Locations are tried only while a lease from the request that last confirmed it lasts, on the node's own clock (`Departure::until`, `SendStep::holds`), past which it is presumed lost and audited once; a send already under way keeps its Journey's identifier as the far end's deduplication key (`tests/ledger/send_claim.rs`). A Publication's claims are sent from here only where Xmip Storage's answer says the node holds them (`SendStep::confirmed`), so a Publication asked again after a lost answer sends nothing another node sent meanwhile (`tests/ledger/send_raced.rs`, over `fixture::Failing::lose_answer`). **Admission is the one door to the Send pool** (`src/send_step/admission.rs`, corrected 2026-10-06): a Publication, a resumed Subscription's move (`held_work::pick_up`) and a scan each claim a Journey only under a place the pool admits (`SendStep::admit`) — its most threads less every Journey the node owns, never a retry waiting for its due time, and every place admitted and not yet owned (`SendStep::room`) — and give back a place a write did not take; what has no place stays durable and unclaimed in its queue, which is read again the moment a place frees, so a slow far end leaves its backlog in the Ledger and the node's memory stays bounded by its threads; a scan of a queue that is not ordered claims what it finds on the send thread its place was admitted for, so a backlog's claims share their commits rather than wait one by one on the dispatching (`send_step::dispatch`'s `take`; `tests/ledger/send_bounded.rs`). An act or a Sequential scan decides on a Journey read again under its claim, refusing or passing over one another writer moved after the first read (`tests/ledger/send_raced.rs`, over `fixture::Failing::before`, which lets another writer in between two calls by order, never by timing). A send whose thread panics is settled on the way out (`send_step::dispatch`'s `Sending`): written Failed with why, its claim ended, counted and audited. `SendStep::figures` counts, as history since the node started, what each Send Port sent and failed, the claims it lost, and the last Journey that failed with its reason; and, as its queue stands now, how many wait for a retry's due time as the last read of its queue found them, how many failed Journeys wait in its queue as Xmip Storage counts them in the queue's index of failed Journeys — entered by the failure's own hand-on (`HandOn::failed`) and taken out by an operator's act (`HandOn::cleared`), one that failed before a restart or on another node among them — and the oldest `[tuning] failed_window` of them, the node's one bounded window, read again only where the index moved (`send_step::figures`; open problem 34, corrected 2026-10-16; a scan reads no place marked failed unless it blocks its sequence), and whether one blocks its sequence, and the claims whose renewal Xmip Storage has not answered, with since when. The snapshot publishes a record at `<node>/send/<Port>` for every Send Port the node sends, apart from its Send Locations — Done while failed Journeys wait in its queue, most severe where one blocks its sequence, and Done while a claim's renewal is unanswered, its evidence naming Xmip Storage and since when; Fine once neither is — and every Port's failed Journeys (`PortFigures::published`, `observe::FailedJourneys`): `count` now, zero where none, `blocked`, the window (`send_step::FAILED_WINDOW`, a hundred, by default), and `last_failure` apart, as history; `SendStep::failed_journeys` reads them from the index in Xmip Storage a page at a time, each page one read, for `xmip_failed_journeys_v1` (`tests/ledger/send.rs`, `tests/ledger/send_killed.rs`, `tests/ledger/send_bounded.rs`). A Receive Location's far end that could not be told in a way asking again may mend is audited once for each reason, with the Location and why (`Receiving::audit`, `tests/ledger/untold.rs`). **How a node reaches Xmip Storage** (`src/storage.rs`): the Xmip Storage its program opened itself (`Linked::storage`: a test's Storage node, or a client of the Storage nodes the program built with the identity it presents); otherwise, where the node declares the `storage` role (its document's `roles`, parsed by `node::NodeRole::declared`) and `[storage]` lists no Storage node, the node is its own embedded Storage node, and one declaring neither the role nor `[storage] nodes` is refused at phase 3 in words naming both (ADR-0056, amendment 2026-10-20) — each data domain's database where its table — `[runtime]`, `[administration]`, `[audit]`, its `storage` and its `connection` — says, and where one is left out `RocksDB` at `<data>/storage/runtime` and `SQLite` at `<data>/storage/administration.sqlite` and `<data>/storage/audit.sqlite` (`Linked::engine`, `Linked::administration`; `storage::FILES`), a table naming a database server refused at phase 3 while no backend is built (ADR-0070, amendment 2026-10-10), sealed under the key store `[store]` names with the key-encryption key `storage` — refused at phase 3 where the program was not built with both engines and at phase 9 where they do not open or one holds a schema version newer than the build's, each brought to the build's as it opens and published at `<node>/storage/<domain>`, its schema version and engine (`Reached::published`; open problem 41, ADR-0015, amendment 2026-10-20); a node listing Storage nodes is refused at phase 3 unless its program handed it the client, since the identity it presents to them is not configurable yet. `Running::storage` says which, and the chunk. Departure (`src/departure.rs`) is one pass of a Journey to its Send Port: its active Send Location (`src/sending.rs`: a bound Send Port is the Send Location of its name, or those its `send_locations` names in order; a Send Port Group's Ports each by a Journey of their own), `departure::Progress` keeping where it stands between passes, from and into the Journey's `attempts`; it authorizes again — the `location` policy admits each Send Location the node starts (the owner, 2026-10-19) — resolves whose identity the chain declares (ADR-0006) and sends through the Location's transport, its Message a chunk at a time, the Journey's identifier as its deduplication key and the Message's context with it (`transport::Transport::send_from`, `transport::Outgoing::keyed` and `carrying`, runtime-model section 15), what the send holds — six chunks of reading where its transport streams (`budget::STREAM_CHUNKS`, measured at a little over five for a 64 MiB Message), the whole Message besides where it gathers (`transport::Sending`) — held within the node's byte budget for sends, a send with no room waiting for one (`tests/ledger/send_streamed.rs`: a fan-out of 64 MiB to four Ports in bounded memory, and sends that gather more than the budget holds going one at a time); a Work Process destination is `ProcessNotRun`, since a Process is compiled at design time and none is built (ADR-0066 clause 4). What both halves share — the `Runtime`, `Parties` and `PartyDirectory` — is `src/message_path.rs`; its `clock` is read at each gate, and a running node's is `xcore::SystemClock`. The Message treatments are `xmip-core-message`'s; `src/generation.rs` keeps what a generation is.

**For a surface.** Its native library is what the operator surfaces load (`xmip_operate.h`). `start::start`, behind `xmip_start_v1`, is the first three phases alone: it validates and plans a node against the technologies this runtime carries and says in every record that nothing runs, since a surface's process links no technology (whether it may run a node at all is open problem 20); `xmip_validate_v1` reads a node's configuration, its bindings with the Application sections they bind, or a cluster's `xmip.toml` node by node. Section 7 — the rules a surface calls instead of keeping its own — is `src/ffi/rule.rs` and `src/ffi/rule/node.rs`, forwarding each rule to the crate that owns it (`observe::Scope`, its containment, parts, node and stage, `observe::Health`, `observe::Standing`, `observe::Counted`, `observe::capability`, `node::Stage`, `node::Capability`), one call per export and no rule of its own; section 8, `src/ffi/publication.rs`, reads a publication by `observe::Publication`, and `src/ffi/topology.rs` says what a topology kind, origin or pattern is called (ADR-0027 and ADR-0052, amendments). Section 9, `src/ffi/audit.rs`, forwards `xmip_audit_v1` to `xmip-core-audit`'s `ProgramAudit` (ADR-0062), and `xmip_audit_read_v1` to its reader and `AuditQuery`, answering the header's JSON (ADR-0062, amendment 2026-09-29) — with each writer's audit chain walked over the file as it is now where the query asks `verify` (ADR-0070 clause 5); `ffi/rule.rs` forwards the one wildcard, `observe::wildcard`, as `xmip_scope_matches_v1`, and whether what a hidden run made is shown, `observe::run::shown`, as `xmip_run_shown_v1` (ADR-0028, amendment 2026-09-30). Section 10 is the designer's, over the cluster's one `xmip.toml`: `src/design.rs` reads the JSON a surface hands over into `configure`'s types and `src/ffi/design.rs` holds `xmip_cluster_views_v1` (the file as one view per artifact kind, an Xmip Application's routes among them), `xmip_filter_structure_v1`, `xmip_filter_text_v1`, `xmip_cluster_edit_v1` and `xmip_cluster_slices_v1`, each node's document by `configure::slice`, a node's own document refused (ADR-0064, amendment 2026-10-03; ADR-0031, amendment 2026-10-05); the views say `document`, `cluster` or `node`, by `configure::document_kind`, so the Operation Desktop offers no node's file for editing. **The operate plane** (`src/plane.rs`; ADR-0067; ADR-0014, amendment 2026-10-12): how a surface reads, follows and acts on a node on another machine, both ends here, once — gRPC on the estate's own HTTP/2 (`net::http2`) and framing (`net::grpc`), JSON messages (`application/grpc+json`, `plane::call`), inside Xmip's mutual TLS (`xmip-core-library-tls`), no gRPC crate and no async runtime. The node's side is `plane::Listener` over a `plane::Published` — `plane::Board`, which `xmip-service` posts each publication to as it writes its file — answering the publication, a wait on its next revision (`plane::call::LONGEST_WAIT` at most) and an operator's act: the caller is the subject of its certificate, admitted by the role `[operate] role` states (`plane::role`, the one gate, `xmip_operate.h` section 18, `src/ffi/security_role.rs`), audited as `act` taken or refused, and applied by `applied::apply`, the one apply of an order an `orders` directory and the listener share. `Running::operate` starts it from `[operate]` (`src/running/operate.rs`): the local endpoint always — decided by the owner, 2026-10-13, *the local endpoint always starts, named `xmip-<node>` unless the configuration names it* (`Running::local_endpoint`) — placed by the one rule `plane::local::place` in `\\.\pipe\` on Windows, `/run/xmip/` on Linux and `/var/run/xmip/` on macOS (`<name>.sock`), a name that would leave the folder refused; the folder is made by the systemd unit's `RuntimeDirectory` and a launchd daemon of its own (`registration::systemd_unit`, `registration::launchd_run_directory`); and the network listener where `[operate] listen` names one. **Local callers are proven by the operating system** (the owner, 2026-10-19; open problem 35): the local endpoint lets open it only the node's account, the machine's administrators and whom `[operate] admit` names — on Windows the pipe's security descriptor, the admitted reading and writing it and never making an instance of it (`plane::local::windows::openers`), every surface opening it lent for identification alone (`ffi::system::open_identifying`), so the node reads the caller's account from its token and can never act as it; on Unix the kernel's word on the peer (`SO_PEERCRED`, `getpeereid`) judged against the same list (`plane::local::unix::Admitted`), the socket `0600` where nobody else is admitted, in a folder the node's account or the superuser owns and nobody else may write (`unix::guarded`). A tcp connection over loopback is trusted for nothing: the network listener asks every caller for its certificate. A call on the local endpoint waits at most `[tuning] local_timeout`, which the node declares beside its endpoint (`plane::deadline::DECLARED`) and `Remote::local` takes where it is given none (`plane::deadline::declared`); a socket keeps that time itself, a pipe's read is cancelled when it passes by the one deadline thread of the process (`plane::deadline`, a thread per surface until 2026-10-21), and the surface says *the node did not answer within* it and is unreachable until the follow hears the node again (`plane::deadline` tests). The surface's side is `plane::Remote`: the publication on an asking connection, the follow on a connection of its own holding the node's wait, and the recovery loop of ADR-0052's note of 2026-10-05 (`plane::remote::RETRY`: 0, 2, 10, 30 seconds, the last repeated), started by the first wait or by a read that finds the node gone, every follower told when the node is lost and again when it is back; every connection reads through `net::watched`, so an end reaches a blocked read within 50 ms. Section 17 exports it (`src/ffi/remote.rs`) and serves this process's node for a program hosting one through the boundary (`src/ffi/served.rs`, over a board it posts to). `tests/plane` proves both ends over loopback with a test authority's certificates (`fixture::Authority`): the publication read, a follower told — a median of about 0.3 to 0.6 ms from post to told, debug build — an act refused to an Observer and audited as the certificate's subject, a stranger's certificate refused, and a node lost, told and found again on the loop; and the local endpoint (`tests/plane/local.rs`): read and followed — a median of about 0.22 ms from post to told — a surface's connection from nothing to its first answer, the caller's account read from the operating system, held under the millisecond (about 0.3 to 0.45 ms the fastest of five, Windows; 0.70 to 0.82 ms on Linux under WSL; debug builds), after four costs were taken out: a name Windows took 0.35 ms to give is kept by the identifier its token proved, one thread for the process keeps every pipe surface's deadline (`plane::deadline`), a connection's thread is kept for the next (`plane::workers`), and both ends ask HTTP/2 where `net` compiled it (`net::http2::BoxedClient`, `BoxedServer`) rather than compiling it unoptimized in the runtime's tests, an act refused to an Observer as the user the test runs as, and a stop and a drop that end a follow waiting on the pipe at once. A test that measures takes the machine whole and every other shares it (`tests/plane/main.rs`, `alone`).

**A Subscription paused.** `src/pickup.rs` is a node's Subscriptions as an operator sees and pauses them: each taken up from the configuration with the Application that draws it, the configuration it is a section of and its entry there (`src/configured_subscription.rs`, from what `start::read` read), and its standing kept in the node's runtime store (`src/store.rs`: the one its configuration's `[store]` places, over RocksDB, the one engine (ADR-0015, amendment 2026-10-01), and a key store the program linked — `Linked::engine`, `Linked::key_stores` — refused at phase 3 when the program was not built with them and at phase 9 when it does not open; or the one the program opened itself, `Linked::store`; in memory where the program linked no engine and the configuration names no store). Routing's matches to a paused Subscription are held — persist's `HeldMessage`, numbered in the order held, counted, nothing lost — and a resume lets them go oldest first, what it matches meanwhile joining the end; a running node picks each up on a thread of its own and moves it, in one hand-on, to the queue of the Send Port its Subscription leads to, from which the send step sends it (`src/held_work.rs`: the identity arrival concluded held in its words and moved with it, read back through the mechanism this node's authenticators declare, departure authorizing again, now). A pause and what it holds survive a restart: the standing is written on every act and hold and read back as the node starts. Every act is audited in the program's audit (`Linked::audit`), and `Running::pickup` hands a node's pickup to its program. `Carried::held` and `Outcomes::held` count what a paused Subscription held.

**Two builds** (ADR-0014, amendment 2026-10-14: the phone follows nodes remotely and runs none). The crate's features say what is compiled; nothing is written twice, each part is gated where it is.

| --- | --- |

The phone's library is `cargo build --release --target aarch64-linux-android --no-default-features --features remote --lib`, with the Android NDK's API-level-26 clang as linker, `CC` and its `llvm-ar` as `AR` for the target, set on the command line or in the environment and never in this repository. It exports the rules, the publication reader, the audit record, the security roles, a person's certificate request and the `xmip_remote_*` client, and needs no CMake: `aws-lc-sys` builds with the NDK's clang. A .NET surface's `RuntimeRules.Load` asks for every export of the full library, so as it stands it refuses the remote one: section 17's five serve exports, sections 10, 12 and 13, and the per-process lists and acts of sections 11, 14, 15 and 16 are not in it.

The C boundary is one folder, `src/ffi/`, and the only place in the runtime that may hold unsafe code (ADR-0050, refined 2026-09-25): the operator's table (`ffi/operate.rs`, over `operator.rs`), starting and validating (`ffi/start.rs`, over `start.rs`), sections 7 to 13, and the loader that opens a module's library (`ffi/loaded_module.rs`, `ffi/loaded_contract.rs`, ADR-0057), which takes a module only when `abi::accepts` — ADR-0012's compatibility rule, beside the descriptor's own in `xmip-core-abi` — does. The library stays in the process once loaded (`xmip_operate.h` section 1): its own threads, the audit keeper and an Event listener, outlive every call, so on Windows it pins itself as it loads (`ffi/resident.rs`) and on ELF systems `build.rs` links it `-z nodelete`; `FreeLibrary` and `dlclose` release a reference and never unmap it (ADR-0027, amendment 2026-09-30). Every enum that crosses `xmip_operate.h` as an `int` is converted in one file, `src/wire.rs`, and every string is lent and read in one, `ffi/text.rs`. `src/registration.rs` generates what each platform's service manager is told about the Xmip Service and its Host Services, for the installer that registers them.
